# 不依賴新服務帳號的交付

- 一般會員登入只顯示 Email／密碼；管理員驗證器欄位只在帳密正確且已啟用 MFA 時出現。原有 TOTP、防重放及一次性復原碼仍由伺服器強制檢查。
- 基本註冊包含暱稱、Email、密碼與確認密碼；Email 貼上前後空白會正規化，重複帳號、弱密碼及錯誤密碼有伺服器防護。新會員為一般會員、0 點、信箱與手機未驗證，不假裝寄信或送簡訊。
- 正式是否開放註冊取決於 ALLOW_REGISTRATION；與 Google、SMTP、簡訊及金流開關獨立。公開開放後仍須真人完成 Turnstile。
- 新增 scripts/operations.mjs health|backup：健康、資料庫就緒及磁碟檢查；SQLite 一致性備份、上傳檔案雜湊、隔離還原、完整性及外鍵檢查。紀錄在 DATA_DIR/ops，只有登入管理員能從後台讀取白名單狀態。
- 正式主機安裝 systemd 排程後，健康檢查每五分鐘、備份每日執行；並非只建立排程檔就算完成，需實際執行成功與排程啟用證據。
- 不自動刪除既有備份。要長期營運，仍須選擇異地儲存目的地與保留政策，設定外部告警收件人，並由帳號本人完成管理員 MFA。
- 商品庫存、營業名稱、客服聯繫、物流、退換貨及個資政策需真實營運資料；不得用虛構內容代替正式設定。
- Google、真實驗證郵件／簡訊、正式充值／退刷與金流付款驅動的 VIP／邀請驗收仍待服務接通。離線 fixture 測試不等於真實供應商驗收。部分退款與逐筆付費／贈點歸因仍採人工處理，不宣稱已完成自動財務。
- 響應式版面可在瀏覽器檢查，但不能代替實體 iPhone／Android 操作、鍵盤及支付返回驗收。
